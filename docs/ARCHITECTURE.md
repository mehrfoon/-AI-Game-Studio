# معماری استودیوی هوشمند

## نمای کلی
کاربر ← مدیر استودیو/هماهنگ‌کننده ← طراحی بازی، داستان، مراحل، هنر، برنامه‌نویسی، صدا، ساخت و QA

## اجزای پیشنهادی
- **GitHub:** منبع اصلی کد و تاریخچه تغییرات.
- **GitHub Issues:** وظایف، باگ‌ها و بازبینی‌ها.
- **GitHub Actions:** تست و ساخت خودکار.
- **لایه مدل‌ها:** رابط قابل تعویض برای مدل‌های متنی و تصویری.
- **هماهنگ‌کننده:** شکستن درخواست به وظایف کوچک، تعیین وابستگی و پیگیری وضعیت.
- **فضای دارایی‌ها:** ساختار مشخص برای تصاویر، مدل‌ها، صداها و فایل‌های بازی.

## چرخه وظیفه
1. مدیر، خروجی مورد انتظار و معیار پذیرش را مشخص می‌کند.
2. عامل مسئول در شاخه کاری جداگانه تغییرات را آماده می‌کند.
3. تست‌ها و بررسی‌های خودکار اجرا می‌شوند.
4. QA نتیجه PASS/FAIL و شواهد را ثبت می‌کند.
5. در صورت شکست، وظیفه اصلاحی به عامل مسئول برمی‌گردد.
6. ادغام و انتشار نهایی طبق سیاست تأیید مالک انجام می‌شود.

## انتخاب موتور
- بازی دوبعدی/سه‌بعدی سبک: Godot گزینه اولیه.
- بازی تحت وب: HTML/JavaScript و کتابخانه مناسب.
- نیازهای خاص: موتورهای دیگر پس از بررسی نیازمندی‌ها.

## محدودیت‌های واقعی
استقلال عامل‌ها به معنی دسترسی نامحدود نیست. هر مدل ممکن است به کلید API، سهمیه یا پرداخت نیاز داشته باشد. GitHub Actions نیز محدودیت زمان و منابع دارد. نسخه اول باید کوچک باشد و با یک هماهنگ‌کننده و گردش‌کار ساده شروع شود.
